# ДЯ · Дальний ящик xdytube

Задачи из этого списка берём в работу по отдельному решению владельца. Текущие правки и их проверки находятся в [плане ближайшего выпуска](next-release.md).

## Оставить сборку для macOS на Apple Silicon

- Убрать workflows, установщики, системные ресурсы и конфигурацию Windows и Linux. Убрать Windows-патч GPUI и `embed-resource`. Пересчитать `Cargo.lock` через Cargo и проверить транзитивные зависимости для macOS. [Cargo.toml](../Cargo.toml) · [build.rs](../build.rs) · [GitHub Actions](../.github/workflows)
- Сократить платформенные ветки окна, иконок, поиска браузера, запуска инструментов, загрузки libmpv и обновлений. Сохранить меню, сочетания `⌘`, обработку `xdytube://` через Apple Events и ручные обновления из приватного GitHub. [Точка входа](../src/main.rs) · [Ссылки](../src/links.rs) · [libmpv](../src/player/mpv.rs) · [Обновления](../src/updater.rs)
- Свести упаковку к одному macOS-процессу для тегов `v<версия>`. Результат — `xdytube.app` в ZIP и `SHA256SUMS.txt`. Сохранить ad hoc-подпись и Homebrew libmpv. Уточнить поддержку обязательной аттестации на тарифе приватного репозитория. [Упаковка](../packaging/macos/build-app.sh) · [Workflow выпуска](../.github/workflows/release.yml)
- Проверить из чистой копии `cargo test --release --locked`, подписанный arm64 ZIP, запуск с чистым профилем, ссылки при холодном и повторном запуске, меню, зелёную кнопку, полноэкранное видео, мини-плеер и PiP. Минимальную версию macOS указать после проверки приложения и libmpv на ней.

## Отделить профиль и хранить сессии в Keychain

- Создать `~/Library/Application Support/xdytube` и отдельный файл запущенного экземпляра. Перенести настройки, подписки, плейлисты и прогресс согласованным чтением SQLite. Сохранить старый профиль для отката. Проверить прерванную и повторную миграцию, отсутствие дублей и одновременную работу с оригиналом. [Хранилище](../src/store.rs) · [Экземпляр](../src/links.rs)
- Хранить OAuth-токены и данные сессии истории в Keychain. После миграции предложить заново подключить нужные виды входа. Проверить сохранение доступа после перезапуска подписанной сборки и удаление соответствующей записи при выходе. [Вход в аккаунт](../src/api/auth.rs) · [Сессия YouTube](../src/api/web.rs)
- Предусмотреть диагностический экспорт без приватного ID SponsorBlock, данных прокси и персональных путей. [Экспорт](../src/import.rs)

## Доработать подключение истории YouTube

- Добавлять Chromium-браузеры после проверки полного сценария. При сокращении платформенного кода сохранить Chrome и Яндекс Браузер. [Поиск браузеров](../src/api/web.rs)
- Использовать отдельный закрытый временный профиль на каждую попытку. Проверить отмену и уборку остатков профиля при запуске после сбоя. Хранение сессии согласовать с задачей Keychain. [Подключение](../src/api/web.rs)
- Рассмотреть команду «Продолжить в Safari», которая открывает видео YouTube с текущей секундой. Дальнейшее воспроизведение и его запись в историю выполняет сайт под активной сессией Safari. [Ограничения Safari](../docs/macos-notes.md#safari-и-youtube)

## Интеграции

- Изучить чтение подписок на Twitch через официальный OAuth Device Code Grant. Первый вариант может открывать эфиры в браузере.
- Рассмотреть ссылку на Boosty или исследовать встроенную веб-вкладку. Способ чтения закрытых постов через официальный публичный API пока не подтверждён. [Контекст](../docs/HANDOFF.md)
